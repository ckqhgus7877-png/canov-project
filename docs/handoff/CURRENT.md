# CANOV 현재 진행 상황

마지막 갱신: 2026-09-20

## 현재 단계

사용자·우현과 27개 항목의 기획 Q&A를 진행 중입니다. 결정사항은 진행 중 체크포인트로 저장했으며 아직 통합 PRD 확정본은 아닙니다. 랜딩 페이지 구현 프롬프트 초안은 작성했지만 프론트엔드·백엔드 구현은 시작하지 않았습니다.

## 확정된 방향

- 서비스명: 카노브 / CANOV
- 아파트 입주민 대상 정기 출장세차 서비스
- 고객 접점: 브랜드 홈페이지와 메신저
- 운영 도구: 디테일러 Android 앱과 관리자 웹
- Android MVP를 먼저 개발하고 Google Play 출시를 목표로 함
- 브랜드 핵심: 차량별 Care Profile, 누적 관리 이력, 표준 작업 기준과 품질 확인
- Claude가 개발 및 1차 오류 수정, Codex가 2차 검증 수행
- Claude 기반 고객 CS 자동화를 제품 목표에 포함
- 세차 상품과 제공 범위는 관련 자료 수령 후 디벨롭
- 첫 개발 대상은 랜딩 페이지이며 이후 고객 신청·백엔드·관리자 웹·Android 앱 순으로 진행
- 랜딩 페이지는 로컬 기본 검사 후 비공개 미리보기 주소에서 검증하고, 사용자 승인 후 공개
- 비공개 미리보기는 테스트 저장소에 연결해 신청 입력·검증·제출·관리자 확인까지 검증하고 실제 개인정보는 사용하지 않음
- 신청 완료 화면에 접수 결과·연락 절차·카카오톡 상담 버튼을 먼저 제공하고, 실제 카카오톡·SMS 자동 알림은 후속 운영 단계에서 추가
- 비공개 미리보기는 비밀번호 또는 승인 계정으로 보호하고 검색 차단만으로 접근 보호를 대신하지 않음
- 랜딩 페이지 기술 조합은 Astro + TypeScript, Supabase 테스트 프로젝트, Cloudflare Workers + Access로 확정
- 브라우저의 Supabase 직접 INSERT는 단순 저장 대안으로만 유지하고, 첫 구현은 Workers API를 사용
- 테스트 신청은 Cloudflare Access로 보호된 읽기 전용 최소 확인 화면에서 확인하며 수정·삭제·내보내기는 제외
- 타이어 공기압·워셔액 같은 간단한 점검과 보충을 서비스 방향에 포함하되 수리·분해·진단은 제외
- 간단한 상태 점검은 기본 제공하고 실제 보충은 고객 동의와 차량별 기준 확인 후 진행
- 보충 동의는 Care Profile에 차량별·항목별로 기록하며 고객이 언제든 철회할 수 있고 실제 보충 결과를 방문 리포트로 안내
- 첫 운영은 본인 확인된 카카오톡·CS 요청을 관리자가 반영하고, 고객 직접 변경 기능은 후속 시작 전에 추가 여부를 다시 확인
- 첫 공개 신청서는 이름·휴대전화·아파트·차량 모델/구분·연락 희망 방식과 개인정보 동의만 받고 상세 차량 정보는 상담·계약 단계에서 수집
- 상담 종료·철회 시 신청 개인정보를 지체 없이 파기하고 미응답·미계약 신청은 최대 90일 후 자동 파기
- 상담용 개인정보 동의는 필수 1개로 받고 마케팅 수신 동의는 별도 선택 항목으로 분리
- 첫 공개 버전에는 마케팅 동의를 넣지 않고 실제 캠페인 계획이 생길 때 별도 승인 후 추가
- 개인정보 핵심 내용은 신청 영역 가까이에 표시하고 전문은 펼쳐보기와 처리방침 링크로 제공
- 비공개 미리보기에는 운영 정보가 확정 전임을 표시하고 실제 운영 주체·문의 연락처가 확정되기 전에는 공개 차단
- 개인정보 안내·동의 문구 초안은 운영 정보 빈칸 표식과 함께 작성하되 법적 근거와 실제 정보를 확정하기 전에는 공개 사용 금지

## 후속 작업 시작 전 반드시 재확인

- [ ] `내 차량 관리` 또는 고객 직접 동의 변경 기능을 시작하기 직전에 사용자에게 다음을 질문한다: "Care Profile의 항목별 보충 동의를 고객이 직접 변경하는 B안 기능을 이번 범위에 추가할까요?"
- 현재 결정은 A안이다. 사용자 재승인 전에는 고객 직접 변경 기능을 구현 범위에 넣지 않는다.
- B안 승인 시 기존 차량별·항목별 동의 데이터와 이력을 그대로 사용하고 고객 인증·권한·직접 변경 화면만 확장한다.
