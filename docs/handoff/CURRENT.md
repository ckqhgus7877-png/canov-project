# CANOV 현재 진행 상황

마지막 갱신: 2026-09-29

## 현재 단계

사용자와 진행한 58개 선택형 기획 Q&A는 완료했습니다. 추천 가능한 운영·권한·CS 항목은 사용자 위임에 따라 PM 추천안으로 확정했고, 외부 자료와 실제 계약·법률 검토가 필요한 항목만 보류했습니다. 체크포인트는 아직 통합 PRD 확정본이 아니며 랜딩 페이지 구현도 시작하지 않았습니다.

## 확정된 방향

- 서비스명: 카노브 / CANOV
- 아파트 입주민 대상 정기 출장세차 서비스
- 고객 접점: 브랜드 홈페이지와 메신저
- 운영 도구: 디테일러 Android 앱과 관리자 웹
- Android MVP를 먼저 개발하고 Google Play 출시를 목표로 함
- 브랜드 핵심: 차량별 Care Profile, 누적 관리 이력, 표준 작업 기준과 품질 확인
- 화면 디자인은 `https://canov-landing-mvp.vercel.app/`의 라이브 랜딩페이지를 1순위로, 로컬 `코덱스 프로젝트\카노브 랜딩페이지`의 로고를 보조 기준으로 사용
- Codex가 기획 정리·개발·테스트·오류 수정을 주도하며 중요한 변경에는 Claude 추가 검토를 제안하고 전달용 프롬프트 작성
- 사용자가 프롬프트를 Claude에 전달하고 검토 결과를 가져오면 Codex가 타당성을 확인해 필요한 수정·재검증 수행
- 서버측 AI 기반 고객 CS 자동화를 제품 목표에 포함하며 첫 CS 기능은 OpenAI API로 시험하고 운영용 AI 제공업체는 개발 도구와 별도로 최종 선정
- 세차 상품과 제공 범위는 관련 자료 수령 후 디벨롭
- 첫 개발 대상은 랜딩 페이지이며 이후 고객 신청·백엔드·관리자 웹·Android 앱 순으로 진행
- 랜딩 페이지는 로컬 기본 검사 후 비공개 미리보기 주소에서 검증하고, 사용자 승인 후 공개
- 비공개 미리보기는 테스트 저장소에 연결해 신청 입력·검증·제출·관리자 확인까지 검증하고 실제 개인정보는 사용하지 않음
- 신청 완료 화면에 접수 결과·연락 절차·카카오톡 상담 버튼을 먼저 제공하고, 실제 카카오톡·SMS 자동 알림은 후속 운영 단계에서 추가
- 비공개 미리보기는 비밀번호 또는 승인 계정으로 보호하고 검색 차단만으로 접근 보호를 대신하지 않음
- 랜딩 페이지 기술 조합은 Astro + TypeScript, Supabase 테스트 프로젝트, Cloudflare Workers + Access로 확정
- 브라우저의 Supabase 직접 INSERT는 단순 저장 대안으로만 유지하고, 첫 구현은 Workers API를 사용
- 테스트 신청은 Cloudflare Access로 보호된 읽기 전용 최소 확인 화면에서 확인하며 수정·삭제·내보내기는 제외
- 타이어 공기압·워셔액 같은 간단한 점검과 보충을 서비스 방향에 포함하되 수리·분해·진단은 제외
- 간단한 상태 점검은 기본 제공하고 실제 보충은 고객 동의와 차량별 기준 확인 후 진행
- 보충 동의는 Care Profile에 차량별·항목별로 기록하며 고객이 언제든 철회할 수 있고 실제 보충 결과를 방문 리포트로 안내
- 첫 운영은 본인 확인된 카카오톡·CS 요청을 관리자가 반영하고, 고객 직접 변경 기능은 후속 시작 전에 추가 여부를 다시 확인
- 첫 공개 신청서는 이름·휴대전화·아파트·차량 모델/구분과 연락 희망 방식만 받고 상세 차량 정보는 상담·계약 단계에서 수집
- 상담 종료·철회 시 신청 개인정보를 지체 없이 파기하고 미응답·미계약 신청은 최대 90일 후 자동 파기
- 상담 신청 개인정보는 필수 동의 체크박스 없이 처리 내용을 고지하고, 마케팅 동의는 실제 도입 시 별도 선택 항목으로 분리
- 첫 공개 버전에는 마케팅 동의를 넣지 않고 실제 캠페인 계획이 생길 때 별도 승인 후 추가
- 개인정보 핵심 내용은 신청 영역 가까이에 표시하고 전문은 펼쳐보기와 처리방침 링크로 제공
- 비공개 미리보기에는 운영 정보가 확정 전임을 표시하고 실제 운영 주체·문의 연락처가 확정되기 전에는 공개 차단
- 개인정보 처리 안내 문구 초안은 운영 정보 빈칸 표식과 함께 작성하고 고지안의 최종 적합성과 실제 정보를 확인하기 전에는 공개 사용 금지
- 개인정보 문의는 CANOV 전용 이메일을 공식 창구로 두고 카카오톡·CS를 보조 경로로 제공하며 개인 휴대전화는 공개하지 않음
- CANOV 보유 도메인의 개인정보 역할 주소를 별도 업무용 메일함으로 운영하고 친구가 도메인·메일 관리 권한을 인수
- 개인정보 역할 주소는 유료 별도 업무용 메일함으로 운영하고 향후 CS 자동화에는 공식 연동 수단과 최소 권한만 부여
- 개인정보 문의 AI는 분류·승인된 접수 안내·사람 검토용 답변 초안까지만 수행하고 실제 개인정보 조치와 법적 판단은 사람이 승인
- 개인정보 권리 요청은 등록 휴대전화 인증번호 또는 확인 연락과 기존 정보 한 가지 대조로 본인을 확인하고 이메일 접근만으로 처리하지 않음
- 신분증 사본은 기본 요구하지 않으며 등록 휴대전화를 사용할 수 없거나 정보가 불일치하면 개인정보 조치를 보류해 사람이 검토
- 휴대전화 인증번호를 기본 수단으로 사용하고 어려울 때만 등록 번호 확인 전화로 전환하며 고객이 새로 알려준 번호로 바로 확인하지 않음
- 인증번호는 6자리·5분·일회용이며 재발송 시 이전 번호를 폐기하고 반복 실패·과다 발송을 제한
- 인증번호 발송 서비스는 CANOV 운영 주체 명의로 계약하고 친구가 결제·복구·관리 권한을 인수하며 개발자는 최소 권한만 사용
- 낮은 초기 문자 발송 예산 한도와 사용량 알림을 적용하고 한도·이상 사용 시 자동 발송을 중단해 등록 번호 확인 전화로 전환
- 문자 인증 제공업체는 공개 준비 단계에서 운영 정보 확정 후 공식 업체 2~3곳을 비교해 친구 승인으로 가입하며 그전에는 모의 발송 사용
- 첫 공개 개인정보 권리 요청은 이메일·카카오톡·CS로 접수해 하나의 내부 기록으로 통합하고 고객용 셀프서비스 화면은 후속 단계로 미룸
- 개인정보 권리 요청은 일반 상담과 분리된 Supabase 기록과 Access 보호 내부 화면에서 관리하며 Workers 권한 검사와 변경 감사기록을 적용
- 별도 사무직원 없이 사장이 전체 운영·고위험 결정을 맡고 AI가 단순 CS를 처리하며 디테일러는 배정 고객의 현장·작업 상담만 담당
- 환불·보상·분쟁·개인정보·정책 예외는 사장에게 연결하고 사장 부재 시 사전 지정된 대체 책임자의 제한 권한만 임시 활성화
- 고객과 직원은 CANOV 소유 채널에서 대화하고 AI 미해결 상담을 배정 직원에게 연결하며 개인 전화번호·개인 카카오톡은 공개하지 않음
- 첫 출시는 공식 카카오톡 채널 또는 같은 형태의 공용 상담함을 앱·웹 버튼에 연결하고 자체 실시간 채팅은 후속 검토
- AI 답변은 `CANOV AI 안내`, 직원 답변은 회사 소속과 승인된 업무용 표시명으로 구분하고 개인 연락처·신상정보는 비공개
- 단지 한 곳에서 하루 40~60대를 처리하므로 차량별 위치·순서·진행을 직원이 수동 안내하지 않고 고객 조치가 필요한 예외만 30분 목표로 이관
- 일반 상담은 근무시간 2시간 안에 첫 답변하고 목표를 넘기면 사장에게 자동 재이관
- 고객 진행 상태는 단지 `방문 예정·현장 작업 중·현장 종료`와 본인 차량 `예약됨·완료·예외/확인 필요`만 제공하고 순번·위치·예상 시각은 미제공
- 현장 책임자가 단지 시작·종료를 한 번씩 처리하고 차량 완료·예외는 기존 작업 기록에서 생성하며 GPS 자동 확정과 단지 종료 시 일괄 완료는 금지
- 사장이 방문 그룹별 현장 책임자 1명과 필요 시 대체 1명을 지정하고 동시에 한 명만 활성화하며 방문 종료 시 권한 자동 종료
- 고객·차량의 기본 담당 디테일러는 지속 유지하고 특정 방문 임시 변경과 영구 재배정을 구분하며 사장만 변경·인계 승인
- 임시 담당 변경은 적용 방문과 새 표시명, 영구 재배정은 새 기본 담당과 적용일만 영향 고객에게 회사 채널로 안내하고 내부 사유는 비공개
- 담당 변경 안내는 사장 최종 확정 뒤 승인 템플릿으로 중복 없이 자동 발송하고 제한 재시도·실패 알림·정정 안내 적용
- 고객의 담당 변경 요청은 AI가 접수·요약하되 자동 재배정하지 않고 사장이 일정·업무량·숙련도·분쟁·안전을 확인해 유지·임시 변경·영구 변경 중 결정
- 담당 변경의 원문·민감 사유는 사장만 보고 직원에게는 필요한 조치와 결정만 전달하며 당사자 간 직접 대면 해결을 강제하지 않음
- 변경 요청은 즉시 접수 안내, 일반 건은 1영업일 안에 사장 결정, 안전·중대 분쟁은 즉시 알림과 운영시간 내 30분 확인 목표 적용
- 디테일러의 고객 연락처·상세 주차 위치는 배정된 방문 전날부터 작업 완료·동기화까지 최소 기간만 표시하고 예외 연장은 사장 승인·만료 필수
- 첫 CS 자동화는 상담 분류·승인 FAQ 자동응답과 인증된 예약·최소 상태의 읽기 전용 안내까지만 포함하고 변경·취소·환불 등 실행은 제외

## 작업 재개 방법

같은 저장소를 사용하는 새 채팅에서는 `AGENTS.md`, `README.md`, 이 문서와 최신 Git 기록을 먼저 확인합니다. 새 기기에서는 최신 저장소를 받은 뒤 같은 순서로 읽습니다. Codex에게 현재 작업 섹션과 기준 버전을 전달하고 작업을 이어갑니다.

협업 기준은 Codex 주 개발과 중요한 변경의 Claude 추가 검토입니다. 인증·권한, 개인정보, DB 구조·마이그레이션, 결제, AI 업무 실행 범위 등이 검토 대상이며 상세 절차는 `docs/planning/CANOV-development-tools-plan.md`를 따릅니다. 사용자가 Claude에 전달하고 결과를 가져오는 방식으로 진행하며, 아직 받지 않은 검토를 완료했다고 기록하지 않습니다.

첫 CS 기능의 시험 제공업체는 OpenAI API로 확정했습니다. 다만 최종 운영용 AI 제공업체는 미확정이며 실제 상담 품질·응답 속도·비용을 기록·비교한 뒤 선정합니다. 기존 Claude 고정 표현이나 이번 시험 결정을 최종 운영 제공업체 확정으로 해석하지 않습니다.
