작성일: 2026-09-10
상태: 제안. 구현 시작 전 최종 확정 필요.

## 개발 대상

| 제품 | 사용자 | 첫 범위 |
|---|---|---|
| 디테일러 Android 앱 | 현장 디테일러 | 로그인, 배정 일정, 고객·차량 정보, Care Profile, 작업 전후 사진, 체크리스트, 완료 처리 |
| 관리자 웹 | 운영자 | 고객·차량·단지 관리, 예약 생성, 디테일러 배정, 작업 결과와 누적 이력 확인 |
| 브랜드 홈페이지 | 입주민·제휴 관계자 | 브랜드 인트로, 서비스·브랜드 스토리, 이용 방법, 신청·상담 연결 |
| 공통 백엔드 | 앱·관리자 웹 | 사용자 권한, 예약·차량·작업 데이터, 사진 저장, 서버 처리 |
| 고객 CS 에이전트 | 고객·AI·사장·담당 디테일러 | 승인된 지식 기반 답변, 문의 분류, 인증된 예약 조회, 배정 직원·사장 연결, 상담 기록 |

## 추천 도구

| 영역 | 추천 | 용도 |
|---|---|---|
| 모바일 앱 | Flutter + Dart | Windows에서 Android 앱 개발 및 추후 iOS 확장 가능성 유지 |
| Android 환경 | Android Studio + Android SDK | 에뮬레이터, 실기기 연결, 빌드와 출시 |
| 관리자 웹 | React + TypeScript + Vite | 예약·배정·작업 관리 화면 |
| 브랜드 홈페이지 | Astro + TypeScript | 콘텐츠와 이미지 중심의 브랜드 사이트. 랜딩 페이지 기술 조합으로 확정 |
| 백엔드 | Supabase | PostgreSQL DB, 로그인, 사진 저장소, 접근 권한. 랜딩 페이지는 분리된 테스트 프로젝트 사용 |
| 오류 수집 | Firebase Crashlytics | Android 앱 충돌과 오류 확인 |
| 버전 관리 | Git + GitHub 비공개 저장소 | 기획·프롬프트·코드·검증 이력 공유 |
| 자동 검사 | GitHub Actions | 변경 시 정적 검사, 테스트, 빌드 |
| 랜딩 페이지 배포 | Cloudflare Workers + Access | Astro 정적 자산·신청 API 배포, 비공개 미리보기 접근 보호 |
| 앱 출시 | Google Play Console | 내부·비공개 테스트 및 정식 출시 |
| CS 자동화 | Claude 기반 서버측 에이전트 | 카노브 지식 검색, 단순 문의 답변, 상담 요약과 배정 디테일러·사장 연결. 구체 SDK와 호스팅은 상세 설계에서 확정 |

결제사와 회사 소유 상담 채널·메신저 자동 발송 도구는 상품·운영 정책 결정 후 선택합니다. 첫 출시는 공식 카카오톡 채널 또는 같은 형태의 회사 공용 상담함을 우선 사용하고 자체 채팅은 후속 검토합니다. 상담 채널은 팀 계정, 배정 상담함, 기록 보존, 권한 회수와 공식 연동을 지원해야 하며 직원 개인 연락처를 사용하지 않습니다. 세차 상품과 제공 범위는 관련 자료 수령 후 확정합니다.

랜딩 페이지는 Astro + TypeScript, Supabase 테스트 프로젝트, Cloudflare Workers + Access 조합으로 확정합니다. 관리자 웹의 배포 기술은 구현 전 별도로 확정합니다.

## 고객 CS 자동화 단계 제안

| 단계 | 자동화 범위 | 조건 |
|---|---|---|
| A. 상담 지원 | 문의 분류, 답변 초안, 상담 요약 | 운영자가 검토하고 직접 발송 |
| B. 공개 문의 자동응답 | 승인된 FAQ·서비스 안내 자동 답변 | 근거 없음과 미정 정책은 배정 디테일러 또는 사장 연결 |
| C. 인증 정보 안내 | 본인 예약·작업 상태 조회 및 답변 | 고객 인증, 데이터 접근 권한, 감사 기록 |
| D. 업무 처리 | 예약 변경·취소 등 허용된 작업 | 업무별 정책과 최종 확인 절차 확정 후 검토 |

첫 출시에서 적용할 단계는 미정이다. 배정 고객의 현장·작업 상담은 회사 소유 채널 안에서 담당 디테일러에게 연결하고, 환불·보상·차량 손상·결제 분쟁·개인정보 변경과 정책 예외는 사장에게 연결한다. 직원 개인 전화번호·카카오톡은 고객에게 공개하지 않으며 별도 사무직원은 전제하지 않는다.

## Claude 작업과 Codex 검증 절차

1. 한 번에 하나의 기능 섹션과 완료 조건을 Claude에 전달합니다.
2. Claude는 구현 후 관련 검사와 1차 오류 수정을 진행합니다.
3. 변경 커밋, 실행 방법, 검사 결과, 알려진 문제를 Codex에 전달합니다.
4. Codex는 기획 일치, 권한, 데이터 연결, 실패 처리, 회귀 오류를 2차 검증합니다.
5. Claude가 지적사항을 수정한 뒤 Codex가 재검증합니다.
6. 출시 전 고객 신청부터 작업 완료 확인까지 전체 흐름을 통합 검증합니다.
