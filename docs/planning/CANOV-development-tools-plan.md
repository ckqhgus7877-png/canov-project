결제사와 회사 소유 상담 채널·메신저 자동 발송 도구는 상품·운영 정책 결정 후 선택합니다. 첫 출시는 공식 카카오톡 채널 또는 같은 형태의 회사 공용 상담함을 우선 사용하고 자체 채팅은 후속 검토합니다. 상담 채널은 팀 계정, 배정 상담함, 기록 보존, 권한 회수와 공식 연동을 지원해야 하며 직원 개인 연락처를 사용하지 않습니다. 세차 상품과 제공 범위는 관련 자료 수령 후 확정합니다.

랜딩 페이지는 Astro + TypeScript, Supabase 테스트 프로젝트, Cloudflare Workers + Access 조합으로 확정합니다. 관리자 웹의 배포 기술은 구현 전 별도로 확정합니다.

## 고객 CS 자동화 단계 제안

| 단계 | 자동화 범위 | 조건 |
|---|---|---|
| A. 상담 지원 | 문의 분류, 답변 초안, 상담 요약 | 운영자가 검토하고 직접 발송 |
| B. 공개 문의 자동응답 | 승인된 FAQ·서비스 안내 자동 답변 | 근거 없음과 미정 정책은 배정 디테일러 또는 사장 연결 |
| C. 인증 정보 안내 | 본인 예약·작업 상태 조회 및 답변 | 고객 인증, 데이터 접근 권한, 감사 기록 |
| D. 업무 처리 | 예약 변경·취소 등 허용된 작업 | 업무별 정책과 최종 확인 절차 확정 후 검토 |

첫 출시에서 적용할 단계는 미정이다. 배정 고객의 현장·작업 상담은 회사 소유 채널 안에서 담당 디테일러에게 연결하고, 환불·보상·차량 손상·결제 분쟁·개인정보 변경과 정책 예외는 사장에게 연결한다. AI 답변과 사람 답변을 구분하고 사람 답변에는 회사 소속과 사장이 승인한 업무용 표시명을 표시한다. 직원 개인 전화번호·카카오톡은 고객에게 공개하지 않으며 별도 사무직원은 전제하지 않는다.

한 현장에서 하루 약 40~60대를 처리하는 운영을 전제로 차량별 위치·순번·진행 상황을 직원이 수동 상담하지 않는다. AI는 시스템에 기록된 예약 시간대, 단지 공통 상태와 차량별 완료·예외만 안내하고 차량 미확인·출입·안전 등 고객 조치가 필요한 예외만 담당 디테일러에게 이관한다.

고객 표시 상태는 단지 `방문 예정·현장 작업 중·현장 종료`와 본인 차량 `예약됨·완료·예외/확인 필요`로 제한한다. 순번·정확한 위치·세부 단계·예상 완료 시각은 표시하지 않으며 AI가 추측하지 않는다.

현장 책임자는 단지 시작·종료를 각각 한 번만 처리하고, 차량 완료·예외는 디테일러의 기존 체크리스트 완료·예외 등록과 동시에 생성한다. GPS로 상태를 자동 확정하지 않으며 오프라인 전송은 중복 없이 복구하고 잘못된 상태는 원본을 보존한 관리자 정정으로 처리한다.

사장은 방문 그룹마다 현장 책임자 한 명과 필요 시 현장 대체 책임자 한 명을 지정한다. 동시에 한 명만 활성화하며 단독 방문은 자동 지정한다. 책임자 권한은 해당 방문 그룹의 공통 상태와 집계에 한정하고 다른 직원 배정 고객의 상세정보 접근 권한을 추가하지 않는다.

고객·차량에는 기본 담당 디테일러를 지속적으로 유지하고 특정 방문의 담당자를 별도 저장한다. 사장만 임시·영구 재배정할 수 있으며 임시 접근은 방문 후 제거하고 영구 변경은 미해결 상담·Care Profile·주의사항·예정 예약을 인계한다. 과거 작업의 실제 수행자는 변경하지 않는다.

## Claude 작업과 Codex 검증 절차

1. 한 번에 하나의 기능 섹션과 완료 조건을 Claude에 전달합니다.
2. Claude는 구현 후 관련 검사와 1차 오류 수정을 진행합니다.
3. 변경 커밋, 실행 방법, 검사 결과, 알려진 문제를 Codex에 전달합니다.
4. Codex는 기획 일치, 권한, 데이터 연결, 실패 처리, 회귀 오류를 2차 검증합니다.
5. Claude가 지적사항을 수정한 뒤 Codex가 재검증합니다.
6. 출시 전 고객 신청부터 작업 완료 확인까지 전체 흐름을 통합 검증합니다.
