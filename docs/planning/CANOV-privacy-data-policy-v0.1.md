# CANOV 첫 공개 신청 개인정보 수명주기 v0.1

작성일: 2026-09-20  
상태: 첫 공개 신청서의 구현 기준 초안. 실제 개인정보 처리방침과 처리 안내 문구는 공개 전 별도 검토·확정한다.

## 1. 적용 범위

이 문서는 랜딩 페이지의 상담 신청과 서비스 지역 요청에 적용한다. 정기관리 계약, 결제, 작업 사진, Care Profile과 고객 로그인 데이터의 전체 보존 정책을 대신하지 않는다.

### 공개 전 운영 주체 확인

- 비공개 미리보기에는 운영 주체 정보가 확정 전인 테스트 환경임을 표시하고 실제 개인정보 입력을 금지한다.
- 실제 공개 전에 운영자·사업자 명칭, 개인정보 문의 연락처, 처리방침 시행일과 실제 신청 처리 책임 주체를 확인한다.
- 임의의 이름이나 연락처, 미리보기용 표시값과 빈칸 표식은 공개 문구에 사용할 수 없다.
- 개인정보 처리 안내 전문, 개인정보 처리방침과 신청 화면의 운영 정보가 모두 일치해야 한다.
- 필수 운영 정보가 확정되지 않았거나 서로 다르면 실제 개인정보를 받는 공개 신청 기능을 열지 않는다.

### 개인정보 문의 접수 경로

- CANOV 보유 도메인의 역할 주소를 전용 개인정보 이메일이자 공식 문의 창구로 사용한다.
- 확정된 카카오톡·CS 문의 경로를 보조 접수 수단으로 함께 안내한다.
- 친구의 개인 휴대전화 번호를 공개 연락처로 사용하지 않는다.
- 친구가 개인 이메일과 분리된 업무용 메일함에서 역할 주소의 문의를 관리하게 하고 개발자의 개인 계정에 종속시키지 않는다.
- 도메인·메일 관리자 계정에 다중 인증을 적용하고 복구 수단과 갱신 정보를 안전한 인수인계 문서로 관리한다.
- 비밀번호와 복구 코드는 메신저 평문이나 Git에 저장하지 않는다.
- 외부 회신 전 발신 주소와 SPF·DKIM·DMARC 등 메일 인증 설정을 확인한다.
- 모든 경로의 열람·정정·삭제·처리정지·신청 철회 요청은 하나의 요청 기록 기준으로 관리한다.
- 접수 경로와 시각, 요청 유형, 처리 상태, 처리자와 완료 시각을 기록하되 개인정보 원문을 여러 시스템에 불필요하게 복제하지 않는다.
- 요청 처리에 필요한 범위에서 본인을 확인하고 과도한 신분증 사본을 기본 요구하지 않는다.
- 요청별 법정 처리기한과 절차를 공개 전 확인하고 담당자·내부 처리 목표·지연 시 안내 방법을 정한다.
- 실제 이메일·보조 문의 경로와 담당자가 확정되고 수신 테스트를 통과하기 전에는 공개하지 않는다.

## 3. 개인정보 처리 안내 화면 구성

상담 신청은 계약 체결 전 고객 요청 처리에 필요한 최소 정보로 기획하며 필수 개인정보 동의 체크박스를 두지 않는다. 법적 근거 후보는 개인정보 보호법 제15조제1항제4호이고 공개 전 실제 운영 흐름에 대한 최종 적합성 검토가 필요하다. 문구 초안은 `CANOV-registration-privacy-copy-draft-v0.1.md`를 사용한다.

### 상담 신청 처리 안내

- 목적: 서비스 가능 여부 확인, 상담 연락과 신청 처리
- 항목: 이름, 휴대전화, 아파트·지역, 차량 모델·차량 구분, 연락 희망 방식
- 보유기간: 상담 종료·철회 시 지체 없이 파기. 미응답·미계약은 최대 90일. 계약 전환 시 필요한 최소 정보만 계약 기록으로 이전하고 신청 원본의 중복 개인정보 파기
- 선택 권리: 온라인 상담 신청을 원하지 않으면 제출하지 않을 수 있으며, 제출하지 않으면 온라인 상담 처리가 시작되지 않음

신청 버튼 전에 목적, 항목, 보유기간과 선택 권리를 바로 표시하고 상세 전문은 펼쳐보기로 제공한다. 개인정보 처리방침으로 이동하는 링크도 함께 제공하되 링크 방문을 동의로 처리하지 않는다. 펼쳐보기를 열고 닫아도 신청서 입력값을 유지하며 모바일·키보드·화면 읽기 도구에서도 내용을 확인할 수 있게 한다.

### 선택 마케팅 동의

- 상담 신청 처리 안내와 별도의 기본 해제 체크박스로 분리한다.
- 동의하지 않아도 상담 신청과 서비스 이용을 허용한다.
- 실제 추가 전 발송 주체, 채널, 내용, 빈도, 이용 항목, 보유기간과 철회 방법을 확정한다.
- 첫 공개 버전에는 마케팅 동의 항목과 마케팅 동의값 수집을 포함하지 않는다.
- 실제 캠페인·혜택 알림 계획이 생기고 사용자가 추가를 승인한 뒤에만 선택 항목으로 도입한다.

첫 공개 버전은 서버가 관리하는 적용 안내 문구 버전과 안내 적용 시각을 기록한다. 브라우저가 보낸 임의의 문구 버전을 신뢰하지 않는다. 개인정보 수집·이용 동의 여부를 만들거나 동의한 것으로 기록하지 않으며, 증빙만을 이유로 불필요한 IP 주소나 기기 식별정보를 추가 수집하지 않는다.

## 4. 상담 상태

- `submitted`: 접수됨
- `contacting`: 상담 연락 진행 중
- `awaiting_customer`: 고객 응답 대기
- `closed_no_contract`: 계약 없이 상담 종료
- `withdrawn`: 고객 철회 또는 삭제 요청
- `contracted`: 계약으로 전환
- `duplicate`: 중복 신청
- `test`: 테스트 신청
- `spam`: 스팸 또는 비정상 신청

상태 변경 주체, 시각과 사유를 기록하되 불필요한 상담 원문을 로그에 복제하지 않는다.

## 5. 보유기간과 파기 기준

### 계약 없이 종료·철회

- 고객이 가입 거절, 신청 철회 또는 삭제를 요청하거나 서비스 불가로 상담을 종료하면 지체 없이 파기 대상으로 전환한다.
- 자동 파기 작업은 매일 실행해 파기 대상이 계속 남지 않게 한다.

### 미응답·미계약

- 고객 응답이 없으면 신청 접수 시각부터 최대 90일 보관한다.
- 고객의 의미 있는 응답이 있으면 마지막 고객 응답 시각부터 최대 90일을 계산한다.
- 운영자가 일방적으로 보낸 전화·문자·자동 알림과 내부 메모는 만료일을 연장하지 않는다.

### 계약 전환

- 계약·운영에 필요한 최소 정보와 유효한 동의 기록만 고객·차량·계약 영역으로 전환한다.
- 전환 성공과 대상 데이터 확인 후 상담 신청 원본의 중복 개인정보를 파기한다.
- 계약 데이터의 보유기간은 별도 운영·법정 보존 정책에서 정한다.

### 테스트·중복·스팸

- 확인 후 지체 없이 파기한다.
- 테스트 데이터는 실제 인물의 정보를 사용하지 않는다.

### 법령상 보존

- 다른 법령에 따라 보존해야 하는 정보가 있으면 법적 근거, 보존 항목과 기간을 기록한다.
- 상담 신청 데이터와 분리해 접근 권한을 제한하고 보존기간 종료 후 파기한다.

## 6. 파기 구현 기준

- `retention_expires_at`을 데이터로 관리하고 매일 자동 파기 대상을 검사한다.
- 상담 종료·철회·중복·테스트·스팸은 90일 만료를 기다리지 않고 파기 대상으로 전환한다.
- 소프트 삭제 표시는 최종 파기를 대신하지 않는다. 운영상 유예가 필요하면 짧은 기간과 접근 차단 기준을 별도로 승인받는다.
- 파기 로그에는 실행 시각, 대상 건수, 성공·실패와 재시도 상태만 남기고 이름·전화번호·상담 원문을 기록하지 않는다.
- 자동 파기 실패를 운영자에게 알리고 성공할 때까지 재시도한다.
- 백업에서 복원할 때 이미 파기된 개인정보가 다시 활성화되지 않도록 파기 목록 또는 재파기 절차를 둔다.

## 7. 계약 전환과 통계

- 계약 전환은 필요한 필드의 목적 있는 복사로 처리하며 신청 원본 전체를 고객 레코드로 그대로 승격하지 않는다.
- 서비스 지역 수요 통계는 개인과 연결되지 않는 집계 정보만 남긴다.
- 소수 신청으로 개인을 다시 추정할 수 있는 단지별 통계는 공개하지 않는다.

## 8. 접근·표시 기준

- Cloudflare Access로 승인된 운영자만 읽기 전용 신청 확인 화면에 접근한다.
- 목록의 휴대전화는 일부 마스킹한다.
- 상세 개인정보는 상담 업무에 필요한 운영자만 확인한다.
- 수정·삭제·내보내기 기능은 첫 읽기 전용 화면에 제공하지 않는다.
- 키, 개인정보 원문과 Access 토큰을 애플리케이션 로그에 남기지 않는다.

## 9. 양도 전 확인

실제 운영과 고객 데이터를 친구 또는 다른 사업자에게 양도하기 전 개인정보 이전의 법적 근거, 정보주체 통지, 처리방침 변경과 접근 권한 회수 절차를 별도로 검토한다. 비공개 미리보기의 테스트 데이터는 운영 양도 대상으로 사용하지 않는다.
