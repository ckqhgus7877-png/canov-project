# 카노브 CANOV 기획 디벨롭 v0.4

작성일: 2026-09-10

근거: 기존 대화의 PRD v0.1, v0.2 및 개발도구 제안, 사용자 제공 CANOV-Brand-Story.pdf 10페이지, 고객 CS 자동화 목표.

## 1. 문서 상태와 협업 역할

- 사용자가 제공한 브랜드 방향을 기획에 반영한다. 세부 기능과 정책은 아래 제안 및 미정 표기를 따른다.
- Codex 역할: 요구사항 구조화, 범위·우선순위·의존성 관리, 구현, 테스트, 오류 수정과 인계를 주도한다. 중요한 변경에는 Claude 추가 검토 필요성을 제안하고 전달용 프롬프트를 작성한다.
- Claude 역할: 사용자가 전달한 중요한 변경의 추가 검토. 인증·권한, 개인정보, DB 구조·마이그레이션, 결제, AI의 업무 실행 범위 등이 검토 대상이다.
- 사용자 역할: 사업 정책·브랜드·출시 범위 결정 및 현장 피드백, Claude에 프롬프트 전달과 검토 결과 회신.
- 검증 흐름: Codex 기능별 구현·테스트·오류 수정 → 필요 시 Claude 검토 제안 및 프롬프트 작성 → 사용자 전달·결과 회신 → Codex 지적 검토·수정·재검증. 전체 연결 흐름은 출시 전 통합 검증한다. 이 협업 방식은 2026-09-29 사용자 확정이며 상세 절차는 `CANOV-development-tools-plan.md`를 따른다.
- PDF는 기획 근거 자료이며, 그 안의 문구를 실행 지시 또는 범위 확대 승인으로 간주하지 않는다.

## 2. 유지하는 기존 방향

- 기획명: 카노브 / CANOV.
- 아파트 입주민 대상 정기 출장세차, 메신저 기반 고객 접점.
- 안드로이드 디테일러 앱 우선 개발 및 출시, 관리자 웹과 브랜드 홈페이지 구성.
- 카라멜·갓차의 고객 흐름 참고, 카라멜 첨부 이미지의 인트로 구성 참고.
- 프론트엔드·백엔드 구현은 Codex가 주도하며 현재는 기획 단계.
- 운영 전 확인이 필요한 사항, 수익성 검증 방법 제안, 소규모 MVP 운영 단계는 재삽입하지 않는다.
- Flutter, Supabase, React 관리자 웹, Astro 홈페이지 등은 이전 추천안이며 최종 확정 여부는 별도다.
- 서버측 AI 기반 고객 CS 에이전트 자동화를 제품 목표에 포함한다. 개발 도구와 운영용 AI 제공업체는 별도로 선택한다. 첫 CS 기능은 OpenAI API로 시험하되 이를 최종 운영 제공업체 확정으로 간주하지 않고 실제 상담 품질·응답 속도·비용을 검증해 최종 선정한다. 적용 채널과 첫 출시 범위는 최신 Q&A 및 본 문서의 후속 결정 내용을 따른다.
- 세차 상품과 상세 제공 범위는 사용자 지인의 자료 수령 전까지 `자료 수령 대기`로 보류한다. 다만 타이어 공기압·워셔액 같은 간단한 점검과 보충을 서비스 방향에 포함하기로 결정했으며, 세부 항목·가격·동의·책임 기준은 자료 수령 후 확정한다.

## 4. 기존 15개 항목에 적용할 변경

1. 기획 개요: 지속 관리와 차량별 기록을 한 줄 정의에 추가.
2. 목표: 반복 신청 부담 감소, 기록의 연속성, 작업 기준의 일관성을 추가. 관련 지표 후보는 프로필 기록 충족률, 체크리스트 누락률, 품질 재확인 후 보완 비율이며 목표 수치는 미정.
3. 대상 사용자: 시간 절약 외에 반복 설명 없이 차량 특성을 기억해 주는 관리에 대한 수요를 가설로 추가.
4. 핵심 가치 제안: 차량별 관리 기준, 누적 이력, 담당자 변경 시에도 이어지는 관리.
5. 주요 기능: Care Profile, 방문 이력, 표준 체크리스트, 품질 재확인과 고객 CS 자동화를 제안 기능으로 추가.
6. 이용 흐름: 방문 전에 이전 기록 조회, 작업 후 확인 결과 및 다음 방문 참고사항 기록. 고객 문의는 AI 답변, 배정 디테일러 연결 또는 사장 연결 흐름으로 분기.
7. 운영 방안: 기본 작업 기준과 차량별 주의사항을 함께 적용. 담당자 교체 시 기록 인계. CS 지식과 배정 디테일러·사장 연결 기준을 사장이 관리.
8. 수익·비용: 기존 후보 유지. 간단한 점검·보충 방향은 반영하되 자료 없이 가격·추가 과금과 상세 정비 상품을 확정하지 않는다.
9. 실행 계획: 데이터·권한 설계에 프로필과 이력을 포함하고 현장 작업 기능에 체크리스트와 품질 확인을 연결. CS 자동화는 지식 기반, 상담 기록, 배정 디테일러·사장 연결, 허용된 업무 처리 순으로 단계화.
10. 홍보: 시간 절약 → 차량을 기억하는 관리 → 동일한 기준의 작업이라는 서사 추가.
11. 위험 요소: 기록 누락, 과거 이력 덮어쓰기, 점검 체크만 하고 실제 작업은 누락되는 문제와 CS 에이전트의 근거 없는 답변·잘못된 업무 처리를 제품 검증 항목으로 추가.
12. 의사결정: 간단한 점검은 기본 서비스로 제공하고 실제 보충은 Care Profile의 차량별·항목별 상시 동의와 차량 기준 확인 후 수행. 첫 운영은 본인 확인된 CS 요청을 관리자가 반영하며, 고객 직접 변경 기능을 시작하기 전에 추가 여부를 다시 확인한다. 첫 공개 신청서는 이름·휴대전화·아파트·차량 모델/구분·연락 방식만 수집하고 상세 차량 정보는 상담·계약 단계로 분리한다. 상담 종료·철회 시 지체 없이 파기하고 미응답·미계약 신청은 최대 90일 후 자동 파기한다. 첫 공개 버전에는 마케팅 동의를 넣지 않는다. 상담 신청 개인정보는 계약 체결 전 고객 요청 처리에 필요한 최소 정보로 기획하며 필수 동의 체크박스 없이 처리 내용을 고지한다. 안내 핵심 내용은 신청 영역 가까이에 바로 표시하고 전문은 펼쳐보기와 처리방침 링크로 제공한다. 개인정보 문의는 CANOV 보유 도메인의 역할 주소와 일반 상담에서 분리된 유료 업무용 메일함을 공식 창구로 두고 카카오톡·CS를 보조 경로로 제공하며 개인 휴대전화는 공개하지 않는다. 첫 공개에는 개인정보 권리 셀프서비스 화면을 두지 않고 모든 채널의 요청을 하나의 내부 기록에 등록해 본인 확인 후 처리한다. 권리 요청은 일반 상담과 분리된 Supabase 테이블 및 Access 보호 내부 화면에서 관리하고 Workers가 담당자 권한을 검사하며 모든 변경을 감사기록으로 남긴다. AI는 개인정보 문의 분류·고정 접수 안내·사람 검토용 초안까지만 수행하고 실제 조회·변경·삭제와 법적 판단은 사람 승인으로 제한한다. 개인정보 권리 요청은 등록 휴대전화 인증번호를 기본으로 확인하며, 이용이 어려울 때만 등록 번호 확인 전화와 기존 정보 한 가지 대조로 전환하고 이메일 접근만으로 처리하지 않는다. 인증번호는 6자리·5분·일회용으로 운영하고 재발송 시 이전 번호를 폐기하며 반복 실패·과다 발송을 제한한다. 발송 서비스는 CANOV 운영 주체 명의로 계약하고 친구가 결제·복구·관리 권한을 인수하며 개발자는 분리된 최소 권한만 사용한다. 낮은 초기 예산 한도와 사용량 알림을 적용하고 한도·이상 사용 시 자동 발송을 중단해 등록 번호 확인 전화로 전환한다. 제공업체는 공개 준비 단계에서 실제 운영 조건으로 2~3곳을 비교해 친구 승인 후 가입하며 그전에는 모의 발송 모듈을 사용한다. 별도 사무직원 없이 사장이 전체 운영·고위험 결정을 맡고 AI가 단순 CS를 처리하며 디테일러는 배정 고객의 현장·작업 상담만 담당한다. 비공개 미리보기에는 운영 정보가 확정 전임을 표시하고 실제 운영 주체·문의 경로가 확정되기 전에는 공개하지 않는다. 고지안의 최종 적합성·문구, 고객과 담당 디테일러의 회사 소유 대화 채널, 등록 휴대전화 이용 불가 시 예외 절차, 인증번호 제공업체·요금제·세부 한도·예산 금액, 가격, 상세 체크리스트, 프로필 작성·수정 권한, 품질 확인 담당과 기타 CS 운영 세부 기준은 후속 결정 대상.
13. 요약: 지속 관리·차량별 기록·표준화 세 축 반영.
14. 확인 질문: 아래 미정 사항에서 우선순위에 따라 선택.
15. 페르소나: 고객의 반복 설명 부담, 디테일러의 이전 이력 필요, 운영자의 품질 확인 필요 추가. 모두 조사 전 가설.

## 5. 신규 기능의 초기 구현 제안

### FP-01 CANOV Care Profile

목적: 담당자가 바뀌어도 차량의 특성과 이전 관리 내용을 확인한다.
정보 후보: 차종, 색상, 관찰된 외장 상태, 고객이 알려준 주의사항, 오염 특성, 작업 시 유의점, 최근 확인일·기록자.
첫 버전은 사람이 기록하고 조회하는 구조로 제안한다. 자동 진단·AI 추천은 이번 자료만으로 추가하지 않는다.
기존 사실, 고객 전달 내용, 작업자의 관찰을 구분해 저장하는 방안을 검토한다.
차량 기본 프로필과 매 방문 관찰 기록을 분리해 과거 기록이 최신 값으로 덮이지 않도록 한다.

### FP-02 방문별 관리 이력

정보 후보: 예약·차량·담당자, 방문 시각, 전후 사진, 수행 항목, 특이사항, 다음 방문 참고사항.
다음 담당자가 배정된 차량의 이전 이력을 볼 수 있어야 한다. 타 디테일러 전체 업무 접근과는 구분한다.
검증 예: 두 번째 방문 기록을 추가해도 첫 번째 사진과 메모가 보존되며 올바른 차량에 연결된다.

### FP-03 표준 작업 체크리스트

공통 작업 기준에 차량별 주의사항을 함께 표시하는 구조를 제안한다.
체크리스트 정의와 방문별 수행 결과를 분리하고 적용 버전을 남기는 방안을 검토한다.
검증 예: 기준이 개정돼도 이미 완료한 방문의 수행 결과가 달라지지 않는다.
필수 항목, 해당 없음 사유, 미완료 사유, 완료 차단 조건은 상세 기획에서 정한다.

### FP-04 품질 재확인

작업자가 종료 전 결과를 확인하고 필요한 보완을 기록한다.
관리자 전수 승인 또는 표본 검수 여부는 미정이며 자동으로 전수 승인 구조를 도입하지 않는다.
작업 종료, 자체 품질 확인, 고객 완료 안내를 구분할 필요가 있다. 실제 상태값은 후속 명세에서 확정한다.
검증 예: 미완료·보완 필요 상태가 정상 완료처럼 표시되지 않고 확인 주체와 시간이 기록된다.

### FP-05 서버측 AI 기반 고객 CS 자동화

목적: 반복 문의의 응답 시간을 줄이고 고객이 필요한 안내를 빠르게 받도록 한다.
목표 범위 후보: 서비스 소개, 이용 방법, 예약·작업 상태 안내, 자주 묻는 질문, 상담 접수, 배정 디테일러·사장 연결. 세차 상품·가격·제공 범위에 관한 답변은 승인된 자료가 등록된 이후에만 제공한다.
답변은 승인된 카노브 기획·정책·FAQ·고객별 허용 데이터에 근거해야 하며, 근거가 없거나 정책이 미정이면 추측하지 않고 확인 필요 또는 배정 디테일러·사장 연결로 처리한다.
고객 식별 전에는 공개 정보만 답변한다. 예약·차량·결제 등 고객별 정보는 인증과 권한 확인 후 조회하도록 설계한다.
초기에는 FAQ 답변과 상담원 전달을 중심으로 제안한다. 예약 변경·취소·환불·보상 등 실제 데이터를 변경하는 업무는 정책, 인증, 승인 방식이 확정된 뒤 단계적으로 검토한다.
상담 내용, 사용한 지식 버전, 답변 결과, 상담원 전환 사유를 기록해 오류를 재현하고 지식을 개선할 수 있어야 한다.
검증 예: 승인된 자료에 없는 가격을 질문하면 금액을 생성하지 않으며, 고객별 예약 조회는 인증되지 않은 사용자에게 노출되지 않는다.

## 6. 개정 현장 흐름 제안

배정 일정 확인 → 차량 프로필·이전 기록 조회 → 현장 차량 상태 확인 → 프로필 신규 작성 또는 변경 기록 → 공통 체크리스트·차량별 주의사항 확인 → 작업 및 사진 기록 → 품질 재확인·필요 시 보완 → 완료 기록 및 안내 → 다음 방문 참고사항 전달.
고객 최초 등록·구독 신청은 유지한다. 반복 방문마다 새로 신청할 부담을 줄이는 것으로 해석한다.

고객 CS 흐름: 회사 소유 채널로 고객 문의 접수 → AI가 문의 유형 파악 → 공개 FAQ 또는 인증된 고객 정보에 근거한 단순 답변 → 해결 여부 확인 → 배정 고객의 현장·작업 상담은 담당 디테일러에게 요약과 함께 전달 → 환불·보상·분쟁·개인정보·정책 예외는 사장에게 전달 → 처리 결과 기록. 직원 개인 연락처는 공개하지 않고 첫 운영에는 별도 사무직원을 두지 않는다.

운영 권한은 사장 중심으로 구성한다. 사장은 고객·아파트·차량과 직원을 연결하고 배정·가격 예외·환불·보상·분쟁·개인정보·계정 권한을 최종 승인한다. 디테일러는 자신에게 배정된 아파트·고객·차량과 작업에 필요한 최소 정보만 확인하고 현장 상담과 작업 기록을 처리한다. AI는 승인된 단순 문의·분류·요약·연결만 수행한다. 사장 부재 시에는 사전 지정된 대체 책임자의 제한 권한만 기간을 정해 활성화하고 모든 사용을 감사기록으로 남긴다.

고객과 직원의 상담은 CANOV가 소유한 앱·웹 채팅 또는 공식 카카오톡 같은 회사 채널에 남긴다. AI 미해결 상담을 배정 디테일러에게 전달하되 직원은 자신의 배정 상담만 조회하고 회사 계정으로 답변한다. 담당 변경·퇴사 시 기록은 새 담당자에게 인계하고 이전 접근·세션을 회수한다. 구체 채널과 제공업체는 팀 배정, 기록 보존, 권한 회수, 공식 연동과 비용을 검증한 뒤 확정한다.

첫 출시는 CANOV 공식 카카오톡 채널 또는 같은 형태의 회사 공용 상담함을 앱·웹 상담 버튼에 연결하고 자체 실시간 채팅은 후속 검토한다. 운영 주체가 채널을 소유하고 친구가 관리자·복구 권한을 인수하며 직원별 계정·최소 권한을 사용한다. 공식 도구가 안전한 담당자 배정·기록·권한 회수를 지원하지 않으면 개인 연락처로 우회하지 않고 호환 도구를 다시 선택한다.

AI 답변은 `CANOV AI 안내`, 직원 답변은 `CANOV 담당 매니저 · 승인된 업무용 표시명`으로 구분한다. 고객에게 회사 소속과 현재 담당자를 알리되 개인 연락처와 불필요한 신상정보는 공개하지 않는다. 내부 감사기록은 표시명 대신 변경되지 않는 직원 계정 ID를 사용하고 담당 변경 시 고객에게 새 표시명과 인계 사실만 안내한다.

단지 한 곳에서 하루 약 40~60대를 처리하므로 직원이 차량마다 위치·순서·진행 상황을 수동 안내하지 않는다. AI·시스템은 예약 시간대, 단지 방문 그룹 공통 상태와 차량별 완료·예외만 안내한다. 차량 미확인·주차 위치 오류·출입·안전처럼 즉시 고객 행동이 필요한 예외는 30분 확인 목표로 담당 디테일러에게, 일반 상담은 2시간 첫 답변 목표로 배정하며 목표 초과 시 사장에게 자동 재이관한다.

고객 상태는 단지 방문 그룹 `방문 예정·현장 작업 중·현장 종료`와 본인 차량 `예약됨·완료·예외/확인 필요`만 제공한다. 실시간 순번·대기 수·정확한 위치·세부 단계·예상 완료 시각은 제공하지 않는다. 차량 완료는 체크리스트·사진·품질 조건 충족 후에만 표시하고 단지 종료와 분리한다. 단지 공통 상태는 조회 정보로 제공하며 차량 완료·예외처럼 고객에게 직접 필요한 결과만 별도 알림 후보로 둔다.

현장 책임자가 단지 `작업 시작·현장 종료`를 각각 한 번 처리하고 차량 완료·예외는 기존 체크리스트 완료·예외 등록에서 생성한다. 종료 전에 완료·예외·미처리 건수를 확인하며 미처리 차량이 있으면 사유와 후속 계획을 기록한다. GPS·사진 시각만으로 상태를 확정하지 않고 오프라인 재전송은 중복을 만들지 않으며 잘못된 상태는 원본을 보존한 사장 정정으로 처리한다.

사장이 방문 그룹별 현장 책임자 한 명과 필요 시 현장 대체 책임자 한 명을 사전 지정한다. 단독 방문은 자동 지정하고 동시에 한 명만 시작·종료를 조작할 수 있다. 책임자 변경은 상호 인계 또는 사장 승인과 미처리 현황을 기록하며 역할은 방문 종료 시 자동 종료한다. 현장 책임 권한은 다른 디테일러 고객의 상세정보·상담 접근 권한을 부여하지 않는다.

고객·차량의 기본 담당 디테일러는 지속적으로 유지하되 특정 방문 담당을 별도로 둔다. 사장은 휴무·물량·숙련도·품질에 따라 방문만 임시 변경하거나 기본 담당을 영구 재배정한다. 임시 접근은 방문 후 제거하고 영구 재배정 시 상담·Care Profile·최근 기록·주의사항·예정 예약을 인계하며 과거 실제 작업자는 보존한다. 직원별 기본 고객 수·당일 배정·예상 작업량을 함께 확인해 과도한 편중을 막는다.

임시 방문 담당 변경은 해당 방문과 새 업무용 표시명, 영구 재배정은 새 기본 담당과 적용일만 영향을 받는 고객에게 회사 채널로 안내한다. 개인 연락처와 직원 개인 사정·내부 인사정보는 공개하지 않는다. 사전 변경은 방문 안내와 함께, 당일 변경은 확정 직후 알리고 취소·재변경 시 정정 안내를 발송하며 실패는 사장에게 보고한다.

담당 변경 안내는 사장의 최종 배정 확정 후 승인 템플릿으로 자동 발송한다. 초안 저장에는 발송하지 않고 고객·차량·변경 버전별 중복 방지, 제한 재시도, 실패 알림과 정정 안내를 적용한다. 알림 실패와 관계없이 확정된 배정의 접근 권한과 현재 담당 표시는 적용하고 직원 자유문구 발송은 허용하지 않는다.

고객의 담당 변경 요청은 AI가 접수·구조화해 사장에게 전달하되 자동 재배정하지 않는다. 사장은 일정·업무량·숙련도·미해결 상담·품질·분쟁·안전을 확인해 유지·특정 방문 임시 변경·기본 담당 영구 재배정 중 결정한다. 최종 결정 전에는 담당 관계와 접근 권한을 유지하고, 안전·중대 분쟁 우려는 기존 담당자를 거치지 않고 사장에게 제한 공개로 즉시 이관한다.

담당 변경 요청의 원문과 상세 사유는 사장만 확인하고 디테일러에게는 필요한 조치와 결정만 중립적으로 전달한다. 일반 요청은 즉시 접수 안내 후 1영업일 내 결정 또는 처리 예정 안내, 안전·중대 분쟁은 즉시 사장 알림과 운영시간 내 30분 최초 확인을 목표로 한다. 당사자 간 직접 대면 해결을 강제하지 않고 직원의 설명은 별도 회사 채널에서 받아 출처별로 보존한다.

고객 연락처와 상세 주차 위치는 배정된 방문 전날부터 작업 완료·필수 동기화까지 담당 디테일러에게만 표시한다. 배정 취소·변경 시 즉시 회수하고 미해결 예외의 연장은 사유·만료 시각을 지정한 사장 승인으로 제한한다. 과거 이력에서는 기본 마스킹한다.

첫 CS 자동화는 분류·요약, 승인된 공개 FAQ 자동응답과 본인 인증 후 예약 시간대·단지 공통 상태·본인 차량 완료·예외의 읽기 전용 안내까지 포함한다. 변경·취소·해지·환불·보상·재배정 같은 실제 조치는 실행하지 않고 사람에게 이관한다.

## 7. 홈페이지 브랜드 스토리 반영

카라멜 참고 인트로 → 차량 관리가 미뤄지는 문제 → CANOV의 출발 질문 → 정기 방문 방식 → CANOV Care Profile → 방문할수록 쌓이는 관리 이력 → 표준 작업과 품질 확인 → 상품 안내·상담 연결을 서사 후보로 둔다.
기존 가격 중심 구성과의 최종 섹션 순서는 추후 결정한다.
PDF의 밝은 배경과 청색 제목은 참고 요소이며 최종 디자인 확정으로 간주하지 않는다. 기존 인트로 참고 방향은 유지한다.
화면 디자인은 `https://canov-landing-mvp.vercel.app/`의 라이브 랜딩페이지를 우선 참고하고 로컬 CANOV/CAR CARE 로고를 보조 원본으로 사용한다. 짙은 네이비 `#0D1B2A`, 흰색, Pretendard 중심의 큰 제목, Orbitron 영문 라벨, 고정 헤더, 넓은 여백과 가는 선, 네이비·화이트 교차 섹션과 각진 패널을 공통 시각 언어로 삼는다. 세부 적용과 콘텐츠 경계는 `CANOV-design-reference-v0.1.md`를 따른다.
실제 기록과 이력 화면은 구현 후 브랜드 약속의 근거로 활용한다. 자료 속 사진을 실제 카노브 작업 사례로 표시하지 않는다.
9페이지 공구 사진은 정비업으로 읽힐 수 있어 디테일링 장비·작업 기록·검수 장면 이미지로 교체 제안.
6페이지 서로 다른 차량 이미지는 동일 차량의 전후 비교로 표현하지 않는다.

## 8. 표현과 범위 조정 제안

- 4페이지 '신청 없이도 관리': '첫 신청 이후, 매번 예약하지 않아도 이어지는 정기 관리'로 구체화 제안.
- 5페이지 '필요한 정비와 케어': 타이어 공기압·워셔액 같은 간단한 점검과 보충으로 범위를 한정한다. 수리·분해·고장 진단·법정 점검을 제공하는 것으로 표현하지 않는다.
- 5페이지 '고객이 해야 할 일은 없습니다': '반복되는 세차 예약과 관리 부담을 줄입니다'로 조정 제안. 최초 등록·주차 위치 전달 등 필요한 행동은 남아 있다.
- 9페이지 '좋은 서비스가 아니라': '일관된 서비스를 만드는 시스템'으로 제목 수정 제안.

## 9. 개발 프롬프트 변경 계획

기존 00~10 순서를 유지하고 다음 내용을 삽입한다.
- 00 공통 규칙: 브랜드 약속과 구현 요구사항 연결, 미정 정책 처리, 완료 조건.
- 01 데이터·권한: 차량 프로필, 방문 이력, 체크리스트 정의·버전·결과, 품질 확인 기록.
- 03 관리자 기본 정보: 차량 프로필 확인·수정 범위.
- 05 디테일러 상세: 프로필, 이전 방문 이력, 작업 주의사항.
- 06A 현장 전 확인 및 프로필 기록.
- 06B 체크리스트와 작업·사진 처리.
- 06C 품질 재확인, 완료, 다음 방문 인계.
- 07 관리자 결과: 누락·보완 상태 및 과거 이력 확인.
- 08 홈페이지: PDF의 서사와 기존 인트로 참고자료 반영.
- 09 고객 CS 자동화: 지식 기반, 문의 분류, 인증, 답변, 배정 디테일러·사장 연결, 상담 기록을 별도 섹션으로 작성.
- 10 외부 연동: 확정된 메신저·결제·알림 채널 연결.
- 11 출시 검증: 두 번째 방문, 담당자 교체, 통신 실패, 과거 기록 보존, CS 근거 없음·인증 실패·배정 디테일러·사장 연결 시나리오 추가.

각 프롬프트에는 근거 요구사항 ID, 입력·출력, 권한, 정상·예외 흐름, 완료 조건, 실제 검사 결과 보고를 포함한다.

## 10. 의사결정 반영 상태

- 간단한 점검은 기본 제공하고 실제 보충은 Care Profile의 차량별·항목별 상시 동의와 차량 기준 확인 후 수행한다. 고객 직접 변경 기능은 후속 시작 직전에 재확인한다.
- Care Profile은 차량 기본정보·구조화 항목·자유 메모·주의 부위 사진과 변경 이력을 분리하고 작업 전 `변경 없음·변경 등록`을 필수로 한다. 세부 항목은 우현 자료 수령 후 확정한다.
- 디테일러가 자체 품질 확인 후 완료하고 사장은 위험 작업과 표본 작업을 사후 검수한다. 미완료·보완 필요를 정상 완료로 표시하지 않는다.
- 고객 공개 이력과 내부 작업·품질·분쟁 메모를 분리하고 내부 판단·직원 평가·다른 고객 정보는 공개하지 않는다.
- 공통 상품·체크리스트 기준과 버전은 사장이 승인하고 디테일러는 차량별 관찰·주의사항과 수행 결과만 기록한다. 과거 완료 기록에는 당시 버전을 보존한다.
- 첫 상담 채널은 회사 소유 공식 카카오톡 채널 또는 요건을 충족하는 공용 상담함이며 자체 채팅은 후속 검토한다.
- 첫 CS 자동화는 공개 FAQ와 인증된 최소 상태의 읽기 전용 안내까지 포함하고 실제 데이터 변경 업무는 사람 확정으로 제한한다.
- 환불·보상·차량 손상·결제 분쟁·개인정보·안전·정책 예외와 근거 없는 문의는 사장에게 이관하고 배정 고객의 현장 상담만 담당 디테일러에게 연결한다.

## 11. 자료 수령 대기 항목

세차 상품, 실제 제공 범위, 차량 구분, 작업 항목, 소요 시간, 추가 옵션, 가격 관련 내용은 사용자 지인의 자료를 받은 뒤 별도 디벨롭한다.
자료 수령 전까지 홈페이지 상품 문구, 예약 상품 선택값, 체크리스트, 데이터베이스 상품 구조를 확정하지 않는다.
다른 기능의 기획은 상품을 교체 가능한 기준정보로 취급해 선행할 수 있다.
