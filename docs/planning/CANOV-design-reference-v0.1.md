## 2. 확인한 시각 언어

- 핵심 색상은 짙은 네이비 `rgb(13, 27, 42)` / `#0D1B2A`와 흰색이다.
- 본문과 한글 제목은 `Pretendard, sans-serif`, 일부 영문 라벨·원형 링크는 `Orbitron, sans-serif`를 사용한다.
- 고정 헤더는 네이비 배경에 흰색 로고·작은 영문 메뉴·문의 CTA를 배치한다.
- 첫 화면은 어두운 차량 관리 현장 사진 위에 큰 흰색 한글 제목과 짧은 설명을 겹치는 구조다.
- 데스크톱 1280px 확인 시 H1은 약 110px, 주요 H2는 약 92px의 굵은 제목이며 자간을 좁게 사용한다. 구현에서는 고정값을 복제하지 않고 반응형 `clamp()`와 읽기 가능한 줄바꿈으로 조정한다.
- 섹션 번호와 영문 소제목은 작은 대문자, 넓은 자간과 가는 가로선으로 표시한다.
- 흰색 편집형 섹션과 네이비 시스템 섹션을 교차하며, 넓은 여백·분할 그리드·각진 패널을 사용한다.
- 주요 표현 요소는 4단계 케어 흐름, 아파트 전담 운영 설명, 관리 현장 이미지, 모바일형 CARE REPORT 예시, `STANDARD·RECORD·QUALITY`와 마지막 이중 CTA다.
- 둥근 카드 중심의 일반적인 SaaS 화면보다 직선·얇은 테두리·편집 디자인형 정렬을 우선한다. 원형 요소는 첫 화면의 DISCOVER와 마지막 배경 모티프처럼 제한적으로 사용한다.

## 3. 적용 원칙

- 랜딩페이지의 색상·타이포 위계·여백·선·이미지 톤·CTA 성격을 홈페이지, 관리자 웹과 디테일러 앱의 공통 브랜드 출발점으로 삼는다.
- 운영 화면은 현장 속도와 가독성이 우선이므로 랜딩페이지의 큰 제목과 장식 요소를 그대로 복제하지 않고 동일한 색상·타입·선·상태 규칙으로 단순화한다.
- 라이브 페이지의 문구, 가격, DEEP CARE 항목, 예시 차량·날짜와 문의 링크를 확정 사업 데이터로 복사하지 않는다. 기능·콘텐츠가 충돌하면 최신 Q&A·PRD·개인정보 기준이 우선한다.
- 배경 이미지 위 텍스트에는 충분한 대비를 유지하고 키보드 포커스, 본문 바로가기, 의미 있는 대체 텍스트와 색상 외 상태 표현을 보존한다.
- 로고 비율을 변경하거나 임의 글꼴로 재작성하지 않는다. 밝은 배경에서는 네이비 로고, 어두운 배경에서는 대비되는 흰색 또는 승인된 반전 자산을 사용한다.

## 4. 구현·검증 기록

- 구현 보고서에 참고한 URL, 확인일, 로컬 파일명과 적용한 디자인 토큰을 기록한다.
- 대표 데스크톱과 모바일 화면에서 헤더, 제목 줄바꿈, 섹션 여백, 이미지 크롭, CTA와 키보드 포커스를 비교한다.
- 라이브 기준이 바뀌면 기존 화면을 즉시 덮어쓰지 않고 변경점과 영향 범위를 먼저 기록한다.
- 접근성·성능·확정 기능과 충돌하는 표현은 그대로 복제하지 않고 조정 이유를 남긴다.
